Method v1

Every number on this page was produced the same way. The full write-up is in METHOD.md.

Pick a project

Three open-source iOS projects, each pinned to one exact upstream commit and built with Xcode 26.6 on macOS 26.5.1.

Start from scratch

Each build runs on a fresh build machine with no cache, so every run is a clean build.

Prepare, untimed

Downloads and installs (package resolution, npm, pods) run first and are not part of the result.

Time the compile

Only the compile step is timed, from first command to BUILD SUCCEEDED.

Repeat five times

Five runs per project and machine. The headline is the median; fastest and slowest runs are shown too.

Real conditions

Builds ran in the shared production build pools our customers use, during normal working hours.

Reading the results

  • Use the median. Treat the fastest run as a best case.
  • Times on the most popular machine types, such as Mac mini M2 and Mac mini M4, vary from run to run with overall demand.
  • Five runs per project and machine is a small sample.
  • Results reflect the whole build machine (chip, cores and memory available to the build), not the chip alone.
  • Expensify is pinned to a commit that builds with Xcode 26.6 and runs without its private submodule. React Native is built from source.

Repeat it yourself

  • Method: METHOD.md, and how to run: README.
  • Projects at pinned commits: XcodeBenchmark, Signal iOS, Expensify.
  • Workflows, one per machine type: workflows folder.
  • All runs: data/runs.csv. Summary script: python3 tools/summarize.py.
  • Confirm the chip in the "Environment info" step of each build.
