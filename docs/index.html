What was measured

Clean builds

Every build starts on a fresh build machine with no cache.

Five runs, median

Each app and machine was built five times. Tables show median, fastest, slowest and spread.

Real-world conditions

All builds ran on the same shared build machine pools our customers use, during normal working hours.

Same code, same Xcode

Xcode 26.6 on macOS 26.5.1 everywhere. Each app is pinned to a fixed upstream commit.

Timed step only

The headline is the compile step. Downloads, package resolution, npm and pod installs are logged but excluded.

Notes on reading the results

  • These are production results, measured on the same shared build machine pools customers use and during normal working hours. Build times on the most popular machine types, such as Mac mini M2 and Mac mini M4, can vary from run to run with overall demand. Use the median, and treat the fastest run as a best case.
  • Five runs per app and machine is a small sample.
  • Results reflect the whole build machine (chip, cores and memory available to the build), not the chip alone.
  • Expensify is pinned to a commit that builds with Xcode 26.6 and runs without its private submodule. React Native is built from source.

Repeat it yourself

  • Each app is a public upstream project at a pinned commit: XcodeBenchmark, Signal iOS, Expensify.
  • Workflows (one per machine type): workflows folder.
  • All runs: data/runs.csv. Summary script: python3 tools/summarize.py.
  • Confirm the chip in the "Environment info" step of each build.
